# Mainnet Cutover Runbook

How testnet staging becomes the production service. Ordered — each step's
verification gates the next. The code is already network-parameterized
(`TATUM_NETWORK` drives chains, endpoints, contracts); this document is the
operational procedure, not a code change.

## 0. Read this first — the one rule

**Never point `TATUM_NETWORK=mainnet` at a wallet store that has lived on a
development machine.** Custody material generated on any dev/staging host is
"seen" keys — whoever touched that host could hold the same `wallet.dat` +
password. Production keys are generated fresh on the production host in
step 3, by/for the client, and never leave it.

## 1. Infrastructure (client-owned)

- [ ] Production host up (see hosting notes: dedicated KMS box before real
      funds — a single box is staging-tolerable, not a mainnet end-state)
- [ ] OS hardened: SSH keys only, password auth off, firewall = 22+443 only,
      fail2ban, unattended security updates
- [ ] Docker + docker compose installed
- [ ] Domain delegated (e.g. `crypto-api.<client-domain>`) → A record → host
- [ ] TLS issued (Caddy/nginx + Let's Encrypt, or provider LB + ACM)

## 2. Secrets — client generates, client holds

- [ ] `TATUM_KMS_PASSWORD` — strong random, generated BY the client, stored in
      their vault. Deployer injects it as an env var; nobody else sees it.
- [ ] `TATUM_API_KEY` — client's account key (mainnet-capable on their plan;
      verify notification credits cover expected volume)
- [ ] `ADMIN_API_KEY_HASHES` — sha256 of new production admin keys. Any key
      used during development is retired.
- [ ] `SERVICE_API_KEYS` — new production tenant keys (per client app).
- [ ] `WEBHOOK_SIGNING_SECRET` / `TATUM_WEBHOOK_HMAC_SECRET` — rotated fresh.
- [ ] `ADMIN_ALLOWED_IPS` — client's ops CIDRs only.

## 3. Custody ceremony — on the prod host, fresh wallet

```bash
# KMS_WALLET_FILE=<host path e.g. ./kms/.tatumrc> in .env first
docker compose up -d db api kms        # daemon needs the file mounted
docker compose run --rm kms generatemanagedwallet BTC
# repeat per chain: LTC ETH MATIC TRON BSC DOGE
#   BSC = BNB Chain (Tatum's legacy code; our API chain is 'BNB')
docker compose run --rm kms generatemanagedprivatekeybatch SOL 100
#   or: node scripts/sol-pool-seed.js --count 100

# pair proof per chain, then enroll:
docker exec bitlily-kms node /opt/app/dist/index.js getaddress <signatureId> 0
# X-Admin-Key takes the hex SHA-256 digest of the key (client-side hashing):
#   node -e "console.log(require('crypto').createHash('sha256').update('RAW_KEY').digest('hex'))"
curl -X POST https://<host>/api/v1/admin/custody \
  -H "X-Admin-Key: <sha256-hex>" -H "Content-Type: application/json" \
  -d '{"chain":"BTC","xpub":"…","signatureId":"…","kmsAddress":"…","treasuryAddress":"…"}'
```

- [ ] 7 custody enrollments (BTC LTC ETH MATIC TRON BNB DOGE) + SOL pool
- [ ] **DOGE: enroll the `xpub` form** — the `tpub` re-serialization was a
      testnet quirk; Tatum's mainnet accepts xpub natively
- [ ] **Backup `wallet.dat` + password NOW** — encrypted, off-box, two
      separate locations. This is the point of no return: from here the
      file holds real funds' keys
- [ ] Fund each treasury with real gas (small): sweeps/pumps need native
      balance — BNB, TRX, ETH, MATIC, SOL, DOGE, BTC, LTC

## 4. Config flip

```bash
TATUM_NETWORK=mainnet
TATUM_USE_KMS=true          # boot refuses mainnet without it — the rail
NODE_ENV=production
WEBHOOK_INGRESS_URL=https://<prod-domain>/api/v1/webhooks/tatum
HISTORY_*_API_KEY=…         # mainnet explorer keys (or rely on subs)
DEPOSIT_SUBSCRIBE_CHAINS=…  # e.g. BNB — subscriptions at mainnet codes
WITHDRAWAL_LIMITS=…         # client's real numbers — MANDATORY
WITHDRAWAL_APPROVAL_THRESHOLD=…
CONFIRMATIONS_*=            # raise per chain risk policy
```

- [ ] `docker compose up -d` — migrations run, API healthy on 443
- [ ] `GET /api/v1/health` → 200; `GET /wallets` with prod tenant key →
      provisions all chains from the NEW xpubs

## 5. Webhook subscriptions — recreated at mainnet codes

- [ ] Provision a test wallet → verify Tatum shows `ADDRESS_EVENT` +
      `INCOMING_FUNGIBLE_TX` on `bsc-mainnet` (not `-testnet`)
- [ ] HMAC enrollment re-verified on the new ingress
- [ ] Confirm old testnet subscriptions are dead with the test env — they
      must NOT be reused (bound to the old URL anyway)

## 6. Dust-value smoke tests — real money, tiny amounts

Per chain, before any user onboarding:

- [ ] Deposit ~$5 → webhook/poller detects → confirms → ledger credits →
      `GET /wallets` shows balance
- [ ] Sweep → gas-pump (tokens) → treasury consolidates, real txid resolves
- [ ] Withdrawal ~$2 → KMS signs → broadcast → confirms → ledger debits
- [ ] Recon: on-chain treasury balance == ledger expectations

If a step fails, funds stay on-chain — fix and re-run; never patch the DB
to "agree" with a partial failure.

## 7. Go-live gates

- [ ] `pending:*`/`poll:*` rows at zero or explained
- [ ] KMS signing-request queue clean (no backlog of stale requests)
- [ ] Backups running: `wallet.dat` + pgdata, encrypted, off-box, tested
      restore at least once
- [ ] Alert channel receiving `sweep.failed`/ops notifications
- [ ] `.env` on host scrubbed of TESTNET_*/dev artifacts; admin key
      plaintext nowhere on disk
- [ ] Second KMS host on the roadmap — single-box is signed off as
      staging-only by the client, in writing
